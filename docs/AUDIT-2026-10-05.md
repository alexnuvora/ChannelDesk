## Changes

- Canonical OAuth origin, protected login continuation, callback validation and a consent form bound to the signed-in user and exact request.
- Strict scopes and PKCE; unknown scopes no longer silently grant publishing access. ChatGPT metadata validates its redirect URI.
- Public OAuth discovery bypasses session middleware. Runtime configuration failures return controlled, non-cached errors rather than uncaught exceptions.
- Transactional code consumption/token issuance and refresh rotation. Browser clients cannot invoke privileged grant RPCs.
- Correct correlated workspace predicates. The old unqualified columns could match an inner membership column instead of the outer record.
- Server-only access to encrypted social-token columns, explicit grants, cross-workspace reference checks, publishing role checks and a discoverable `list_workspaces` MCP tool.
- Actual actor attribution, explicit YouTube account/visibility/audience, atomic idempotency claims, atomic results and audit events.
- Public DNS validation, DNS pinning, validated redirects and streamed video uploads with a 256 MB limit. Provider errors no longer return raw response bodies.
- Schedule changes require a private future-scheduled video; they cannot silently hide a public video. UI local schedule time is converted in the browser to an unambiguous ISO instant.
- Protected dashboard layout across all pages; login works for password and Google accounts; existing refresh tokens survive Google reconnect responses that omit them.
- Locked dependencies, lint/typecheck/build gates, focused application and PostgreSQL tests, and migration verification in the existing GitHub workflow.

## Current product gaps

This repository is a YouTube-first foundation, not complete Metricool parity. TikTok, Facebook, Instagram, Threads, LinkedIn, X, Bluesky, Pinterest and Google Business publishing adapters are not implemented. Twitch is listed as planned. The previous Google Business flow linked a Google identity, not a business location, so new connections to that incomplete adapter are disabled. Existing records are preserved.

Media-library uploads, historical analytics, reports, generic cross-channel workers, team-management UI and approval workflows remain unimplemented. The corresponding UI now states these limits. YouTube scheduling uses YouTube's own `publishAt`; there is no generic background scheduler. Uncertain remote outcomes are held for review, with no blind automatic retries.

Before selling this as a multi-tenant product, complete channel approvals, operational monitoring, rate limiting/abuse controls, retention/cleanup for expired OAuth records, token-key rotation, provider revocation/disconnect flows, recovery for long uploads and account lifecycle cleanup. Run a real account-authorisation test and a user-approved private upload; local tests do not certify external API approval or production credentials.
