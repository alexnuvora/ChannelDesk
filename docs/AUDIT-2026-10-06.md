# ChannelDesk implementation review — 6 October 2026

Reviewed GitHub main at `4197474`, including the shared Planner changes. The earlier review describes an older release; this report covers the current YouTube and TikTok implementation.

## Confirmed defects repaired

- Expanded-table RLS used an unqualified `workspace_id` inside membership subqueries. This permitted cross-workspace reads and writes. Policies now correlate to the outer record. Provider inbox/analytics data and approval decisions cannot be forged through direct browser writes. Added explicit server grants and cross-workspace foreign-reference checks.
- The shared Planner's authenticated RPC selected encrypted connection columns and wrote tables for which it had no permission. Scheduling, rescheduling, cancellation and draft editing now use server-only, actor-checked transactions. They do not weaken credential-column permissions or add security-definer workarounds.
- Planner retries did not verify the original payload. Stable request IDs now bind destination, media, settings and schedule. A locked publication cannot be moved after a worker claims it; provider-native schedules are not re-uploaded.
- The worker claimed 20 uploads before processing them sequentially in a 300-second function. It now claims at most three concurrently, uses expiring ownership leases and rejects stale completion writes. Interrupted work and posts missed by over 30 minutes are held for review instead of blindly re-uploaded. Accepted provider results are reconciled on later runs.
- New YouTube schedules from MCP bypassed the shared queue. Dashboard and ChatGPT now use the same Planner service, with generic schedule/reschedule/cancel tools for supported networks. Legacy provider schedules retain their separate management path.
- TikTok local input was interpreted in the server timezone; initial YouTube dates could also use server time. The browser now submits the selected instant with an explicit UTC offset. Invalid calendar dates are rejected. Published posts retain their calendar date after status synchronization.
- Private-bucket assets were anonymously served by UUID and publicly cacheable. UI previews now require workspace access. Provider delivery uses short-lived HMAC links bound to the exact asset and storage key. Responses are not publicly cached; foreign storage paths and active-document MIME types are rejected.
- TikTok uncertain remote results were labelled failed. They now require review. The destination is included in TikTok retry fingerprints; draft status polling uses the proper permission and distinguishes delivery to the TikTok inbox from publication.
- Analytics delete-then-insert imports could erase data on failure or conflict. A transactional upsert now preserves history and computes average viewing duration using view counts.
- Planner draft edits changed the display text without the provider payload and lacked write permission. Edits now update both atomically and remain unavailable during review. Request/approve/reject controls are restored in the Planner.
- The unused Supabase schema helper's public execution grant is revoked when that helper exists.

## Deployment and scheduler

The production project is `channel-desk-61xl`; the Supabase project is `zmwfyrqbgtvtuajbjnzm`. Schema changes continue through the existing Supabase CLI GitHub workflow and its existing `SUPABASE_ACCESS_TOKEN` secret.

The five-minute Vercel cron configuration is incompatible with the observed Hobby plan and was blocking deployments. A GitHub scheduled workflow now invokes the Vercel worker using a two-minute, single-use database ticket issued through the existing CLI credential. No Supabase server keys, channel tokens or permanent shared credentials are exported into workflow logs or source. A completed migration triggers an authenticated dry run that never claims or publishes posts.

GitHub schedules run at five-minute intervals but can be delayed; this is not exact-to-the-minute delivery. At most three new uploads are claimed per invocation. A provider can take additional time to process a video. Use a dedicated durable worker if higher throughput or tighter timing becomes necessary. No hosting-plan change was made.

## Verification and remaining boundaries

Regression checks cover actual PostgreSQL roles/policies, privileged RPC grants, atomic queue claims, reschedule/cancel races, request replay, interrupted workers, analytics rollback, provider link signatures and scheduler ticket expiry/replay. CI also runs lint, type checking and a production build. The migration workflow runs read-only schema assertions and Supabase security advisors.

No live social post or reply is sent as an audit test. Live checks verify deployment, authentication boundaries and the scheduler's dry run. Provider approvals and each account's permissions still govern what can be posted.

YouTube and TikTok are implemented. Other networks, automation execution, Smart Link public pages, competitor metric collection and report delivery still require their adapters/workers; existing tables and navigation do not constitute those integrations. Review/approval is optional, not a mandatory workspace publishing policy. Provider comment replies still require manual review after an ambiguous network failure; there is no automatic retry policy for replies.
